# Auditoría 360° — Credi Marketplace

Fecha de referencia: 22 de septiembre de 2026.

## Objetivo

Validar estabilidad, seguridad, datos, API, DevSecOps, pruebas, Vercel y rendimiento sin declarar como verificado aquello que requiere evidencia externa.

## Fases

1. **Estabilidad y contrato** — Node 24, npm 11.19.1, lockfile v3, Next 16/proxy.ts, estructura.
2. **Verificación de rutas** — auditoría de páginas, APIs, referencias estáticas y duplicados.
3. **Entorno** — auditoría automática de `process.env.*` contra `.env.example` y contrato Zod central.
4. **API security** — matriz estática de autenticación, rol/scope, validación, rate limit e idempotencia; helpers canónicos.
5. **Rate limiting** — RPC distribuido en Supabase; aplicado a checkout, orders y AI assistant.
6. **Supabase/RLS** — RLS de `affiliate_products`, políticas initplan-safe, privilegios de RPC y reconciliación de índices duplicados.
7. **DevSecOps** — CodeQL SAST, Dependency Review y Gitleaks; Dependabot conservado.
8. **Tests** — pruebas unitarias/E2E existentes y regresiones SQL de seguridad 360°.
9. **Performance** — no se eliminan índices solo por aparecer como “unused”; las métricas deben observarse bajo tráfico real.
10. **Vercel** — Preview/Build/Runtime/Firewall/Functions/regions deben verificarse contra el proyecto real; el código no puede falsificar ese estado.

## Decisiones arquitectónicas

- Se conserva Next.js + Vercel + Supabase.
- No se agrega Prisma.
- No se migra a Bun.
- No se cambia de proveedor de infraestructura.
- El modelo sigue siendo modular monolith.
- Creator/admin no es un plan comercial.
- No se inventan tasas fiscales ni estados de producción.
- Webhooks continúan dependiendo de firmas e idempotencia.
- Los pagos siguen siendo transaccionales y no se consideran confirmados por una simple petición del cliente.

## Evidencia Supabase actual

La auditoría de seguridad del proyecto detectó y se corrigió en la base conectada:

- acceso anónimo a `create_b2b_award`;
- acceso anónimo a `settle_order_inventory`;
- RLS faltante en `affiliate_products`;
- políticas duplicadas de `affiliate_products`;
- política duplicada de `b2b_awards`;
- índices duplicados en `affiliate_products` y `b2b_awards`;
- `create_b2b_award` con `search_path` que incluía `pg_temp`.

Queda como advertencia externa de Supabase: **leaked password protection está deshabilitada**. Esta configuración pertenece a Auth/Management y no se debe simular mediante código.

## Vercel

El proyecto Credi está conectado a Vercel y se han generado Previews reales anteriormente. El estado de un deployment debe comprobarse mediante la API de Vercel antes de afirmar `READY`. Si la integración devuelve `pending/building`, se conserva ese estado como pendiente.

## Criterio de salida

No se considera una auditoría 360° cerrada hasta que:

- CI de la rama final esté verde;
- lint, typecheck, unit, E2E y build hayan pasado;
- los workflows de seguridad hayan pasado;
- la migración Supabase esté aplicada y los advisors críticos estén resueltos;
- la Preview de Vercel llegue realmente a estado exitoso;
- la aplicación desplegada responda en health/rutas críticas;
- WAF/Firewall, región y variables de Vercel hayan sido comprobados en el proyecto real;
- no queden fallos críticos de seguridad conocidos sin una justificación documentada.
